# 安全な墨消し（True Redaction）技術要件

最終更新: 2026-10-02（設計文書。未実装）
関連: SPEC §15「True redaction」、CLAUDE.md §10、FEATURES F15.07

> **原則**: 黒い矩形を上に描くだけの「見た目の墨消し」は、元の文字・画像が PDF 内部に残るため、Mavue では**安全な墨消しとして扱わない**。
> UI・ドキュメント・ログのすべてで、「墨消し（Redact）」と「マスク／塗りつぶし注釈（Mask）」を別の機能・別の用語として区別する。

---

## 1. 脅威モデル（何から守るか）

墨消し後の PDF を受け取った第三者が、以下のいずれかで元の情報を復元できてはならない。

| # | 復元経路 | 例 |
|---|---|---|
| T1 | テキスト抽出・コピー＆ペースト・検索 | 黒塗りの下の文字列を選択してコピー、Ctrl+F で検索 |
| T2 | コンテンツストリームの直接解析 | `qpdf --qdf` で展開して `Tj` / `TJ` 演算子を読む |
| T3 | 画像の元データ | 黒塗りした領域の下にある画像 XObject の画素、マスク画像、ソフトマスク |
| T4 | ベクター図形 | 墨消し範囲内のパス（手書き署名、図表の線） |
| T5 | 増分更新の旧リビジョン | 増分保存では旧オブジェクトがファイル末尾より前に残る |
| T6 | 未参照オブジェクト・孤立ストリーム | ページから外しただけでファイル内に残るオブジェクト |
| T7 | 注釈・フォーム | 注釈の外観ストリーム、ポップアップ、フォーム値（`/V`）、フィールドの既定値 |
| T8 | メタデータ | 文書情報辞書、XMP、ページ単位のメタデータ、`/PieceInfo` |
| T9 | 構造・付随情報 | しおり（アウトライン）のタイトル、名前付き宛先、リンク先 URI、タグ付き PDF の `/ActualText` `/Alt`、ページラベル |
| T10 | 添付・埋め込み | 埋め込みファイル、ポートフォリオ、JavaScript、OCG（非表示レイヤー） |
| T11 | OCR テキスト層 | スキャン PDF に Mavue や他ソフトが埋め込んだ不可視テキスト（レンダリングモード 3） |
| T12 | フォント情報 | サブセットフォントのグリフ（ToUnicode CMap から文字種が推測される）※低リスクだが記録 |
| T13 | サムネイル | ページに埋め込まれた `/Thumb` 画像 |
| T14 | 文字幅による推測 | 墨消し箱の幅から語長・語を推測（等幅でない場合）→ 箱を単語境界で拡張するオプション |

## 2. 必要な処理（墨消しエンジンの要件）

### 2.1 対象の確定

- 入力: ページ番号 + 領域（ユーザーの矩形、テキスト選択、検索結果、正規表現などのパターン）。
- 領域は**ページ座標系（回転・CropBox 考慮後）**で保持し、コンテンツ座標へ変換する変換行列を記録する。
- 墨消し前に**プレビュー（マーク段階）**を提示し、「適用」で初めて破壊的処理を行う（Undo は適用前まで。適用後は別ファイルとして保存）。

### 2.2 テキスト（T1, T2）

- コンテンツストリームを解析し、テキスト表示演算子（`Tj`, `TJ`, `'`, `"`）を**グリフ単位**で評価する。各グリフの境界ボックス（フォント行列・Tm・CTM・文字間隔・単語間隔・水平スケーリング・ライズを適用）を計算する。
- 墨消し領域と交差するグリフを**コンテンツストリームから除去**し、残りのグリフの位置を保つため `TJ` の位置調整値を挿入する（後続文字が詰まらないように）。
- 部分的に交差するグリフは**グリフ全体を除去**する（保守的）。
- Form XObject 内のテキストも再帰的に処理する（同じ Form XObject が他ページで使われている場合は複製してから編集する）。
- Type 3 フォントのグリフ（実体はグラフィック）はグラフィックとして扱う。

### 2.3 画像（T3, T13）

- 墨消し領域と交差する画像 XObject / インライン画像について、画像空間へ逆変換した領域の**画素を実際に塗りつぶし**、画像を**再エンコード**して差し替える（元のストリームは破棄）。
- 対象: 通常画像、`/SMask`（ソフトマスク）、`/Mask`（ステンシル・カラーキー）、JPX/JBIG2/CCITT 等すべてのフィルタ。デコードできない形式の場合は**画像全体を除去**する（安全側）。
- 同一画像が複数箇所で使われる場合は複製してから編集する。
- ページの `/Thumb` は削除する（再生成するかは設定）。

### 2.4 ベクター（T4）

- パス構築・描画演算子のうち、領域と交差するものを処理する。第一段階: 交差するパスを**丸ごと除去**（保守的）。第二段階（品質向上）: パスを領域でクリップして外側だけ残す。
- シェーディング（`sh`）、パターンは交差したら除去または領域外にクリップした Form に置換する。

### 2.5 墨消し後の表示

- 除去後、領域に**不透明な矩形（ユーザーが選んだ色）をコンテンツとして描画**する。注釈ではなくページコンテンツとして書き込む（注釈は削除・非表示にできるため）。
- オプション: 理由コード（例: 「非開示」）のオーバーレイ文字列。

### 2.6 注釈・フォーム（T7）

- 領域と交差する注釈は削除する（外観ストリーム、ポップアップ、返信を含む）。
- 交差するフォームフィールドは値を消去し、ウィジェットを削除する（フィールドが別ページにもある場合を考慮）。
- 墨消し時に、全注釈・全フォームのフラット化（または削除）を選べるようにする。

### 2.7 文書全体のサニタイズ（T8〜T11, T13）（「文書を消去」オプション。既定はオン）

- 文書情報辞書・XMP メタデータの削除または最小化。
- しおり・名前付き宛先・リンクのうち、墨消し対象文字列を含むもの、または墨消し領域を指すものを削除する。
- 構造ツリー（タグ）の `/ActualText` `/Alt` `/E` のうち、除去したコンテンツに対応するものを削除する。整合性を保てない場合はタグ構造を削除する（アクセシビリティ低下を警告）。
- 埋め込みファイル、JavaScript、OCG（非表示レイヤー）、`/PieceInfo` を削除する（選択可能）。
- OCR テキスト層（不可視テキスト）は 2.2 と同じグリフ単位の処理の対象に含める（レンダリングモード 3 を区別せず処理）。

### 2.8 保存（T5, T6）

- **増分更新は禁止**。必ず**完全書き換え**で保存する（QPDF で全オブジェクトを再シリアライズし、未参照オブジェクトを除去する。オブジェクトストリームの再生成、xref の再構築）。
- 元ファイルは上書きしない。既定は「名前を付けて保存（`… (墨消し済み).pdf`）」。上書きを選んだ場合も `SafeFileWriter`（一時ファイル → 検証 → アトミック置換）を使い、検証失敗時は元ファイルを残す。
- 暗号化 PDF: 正しいパスワードで復号してから処理し、保存時に暗号化を再適用するかユーザーに確認する。

## 3. 墨消し後の再検証（必須・自動）

保存した**新しいファイルを開き直して**次を検証し、すべて合格した場合のみ「墨消し完了」と表示する。1 つでも失敗したら、完了表示を出さずに失敗内容を示す（ファイルは削除するか「未検証」と明示）。

| 検証 | 方法 |
|---|---|
| V1 テキスト | 墨消し対象として確定した文字列（選択・検索・パターン）が、全ページのテキスト抽出結果に**存在しない**こと（PDFium と、可能なら別実装の 2 系統で抽出） |
| V2 領域内テキスト | 墨消し領域内に残存するグリフが 0 であること |
| V3 画像 | 領域内の画素を再レンダリングして、墨消し色以外が含まれないこと。さらに、領域と重なる画像 XObject をデコードして、対応画素が元データと一致しないこと |
| V4 構造 | 増分更新セクションがないこと（`%%EOF` が 1 つ、`/Prev` なし）。未参照オブジェクトがないこと |
| V5 付随情報 | しおり・注釈・フォーム値・メタデータ・構造ツリーに対象文字列が含まれないこと（全オブジェクトの文字列を走査） |
| V6 OCR | （スキャン PDF）墨消し領域を OCR して文字が検出されないこと（任意・時間がかかるため設定で選択） |

## 4. エンジン・ライブラリ上の制約（DEPENDENCIES.md と整合）

| 構成要素 | 担当 | 制約 |
|---|---|---|
| PDFium | ページオブジェクト API（`FPDFPage_GetObject`, `FPDFPageObj_*`, `FPDFText_*`）で解析・グリフ位置取得・画像取得・オブジェクト削除、`FPDFPage_GenerateContent` で再生成 | **墨消し API はない**。テキストオブジェクトの部分削除（オブジェクト内の一部のグリフだけを消す）は、オブジェクトを分割して作り直す必要がある。保存（`FPDF_SaveAsCopy`）は可能だが、構造の完全なクリーンアップは QPDF に任せる |
| QPDF | 完全書き換え、未参照オブジェクトの除去、暗号化の再適用、オブジェクトストリーム | コンテンツの意味は扱わない |
| Mavue 独自 | グリフ単位の交差判定、TJ 調整、画像画素の消去と再エンコード、サニタイズ、検証 | 実装量・テスト量が最大のリスク（初回レビュー R1） |
| MuPDF（`pdf_redact_page`） | — | AGPL のため不採用（記録済み） |

## 5. テスト要件

- 生成した PDF コーパス: 各フォント種（Type1, TrueType, CID/Identity-H, Type3）、回転ページ、CropBox ≠ MediaBox、Form XObject の入れ子と共有、インライン画像、SMask、JBIG2、OCR 不可視テキスト、タグ付き PDF、注釈・フォーム、増分更新済み PDF、暗号化 PDF。
- それぞれで V1〜V5 が合格すること、墨消し領域外のテキストが**残っている**こと（過剰削除の検出）を確認する。
- 外部ツールでの交差検証（開発時のみ）: `qpdf --qdf` 展開後の文字列検索、別の PDF ライブラリでのテキスト抽出。
- ファジング: 壊れたコンテンツストリームで墨消しエンジンがクラッシュせず、検証で失敗を報告すること。

## 6. UI 要件

- 「墨消し」ツールと「塗りつぶし（マスク）」注釈を別ボタン・別アイコン・別名称にする。
- 適用前に「この操作は元に戻せません。新しいファイルとして保存します」と明示する。
- 完了時に検証結果（V1〜V5）を表示する。検証に失敗した場合は「墨消しは完了していません」と表示する。
- 「マスク」で保存しようとした場合に、墨消しではないことを警告する（保存ダイアログ）。

## 7. 段階的実装計画

1. 解析基盤: PDFium によるグリフ境界ボックスの取得と、交差判定（単体テスト）
2. テキストのみの墨消し + 完全書き換え保存 + V1/V2/V4 検証
3. 画像の画素消去 + V3
4. 注釈・フォーム・メタデータ・構造のサニタイズ + V5
5. ベクターのクリップ、OCR 検証、UI
